# `:core:database`

## Purpose

Owns the main Room database, entities, DAOs, type converters, and migrations for podcasts, queue items, listening history, downloads, RSS episodes, PI episode supplements (cutover dual-read), the first-class local episode catalog (`local_episode_feeds` / `local_episodes`), and episode identity storage: aliases for every stored episode ID, shared like and completion state, and per-show progress of the one-time feed address repair (see [`docs/EPISODE_IDS.md`](../../docs/EPISODE_IDS.md)). It does not own repositories, ranking's separate Room database, playback services, download workers, or feature UI.

## Public API

- `AutoDownloadDao.seedExisting` seeds both `local_episodes` and `rss_episodes` in the activation transaction. `RssEpisodeDao.getByAudioUrl` supports exact push hydration when a GUID is unavailable. Existing tables/keys/schema version are unchanged; `RSS_REFRESH_AUTOMATIC` is a new value in the existing freshness capability field.
- `PodcastDao.getRssNotificationRows` includes every canonical `rss:` row, including disabled/unsubscribed rows and stale source metadata, so notification registration migration can clean up device-owned remote state. This adds no schema migration.

- `PodcastScoring` provides interpretable listening, like, freshness, preference, and optional subscription-recency signals. Canonical Your Shows ranking disables its legacy subscription-recency term so `:core:ranking` can apply one bounded recency policy after normalization; other callers retain the existing `600 / (1 + hours/24)` default.

- `EpisodeListenerStore` (from `BoxLoreDatabase.episodeListenerStore()`, so the playback service reaches it without `AppContainer`) keeps one listener state per episode across its stored IDs ([`docs/EPISODE_IDS.md`](../../docs/EPISODE_IDS.md) §5). An `EpisodeGroup` is every trusted alias of one (show, catalog key), owner first; any other ID is a group of its own and reads and writes exactly as before aliases existed. It works out the owner (the stored mark while that ID holds listener state, else the v39 upgrade's order through `EpisodeIdentityDao.chooseOwner`) and stores it in the transaction of the write that needs it (`historyId`). Reads project (`EpisodeListenerProjection`): the owner's row is the base, and progress, position and play time come from the most recently played row (the owner's, unless a pull, a restore or older-build data put later listening under another ID; an owner that holds only a like never hides another ID's progress); liked and completed are the latest decision across the rows and `episode_group_state`, a group setting winning a tie, so an older alias row can't bring back a cleared like or completion; an episode with one stored ID reads its own row unchanged. `projectRows`, `projectedRows` and `projectCompletedIds` count each episode once (the shared-alias query is watched as a Flow, so episodes with one ID cost nothing extra per emission); `projectCompletedIds` also counts an episode that only its group settings mark completed. `projectRowsByMember`, `projectedRowsByMember` and `projectedLikedIds` list an episode once per stored ID, for screens that look an episode up by the ID they show. `lastPlayedSession` is the projected last session for restores and Android Auto. Writes: `setLiked` writes an absolute like to every trusted ID and the group settings (an episode with one stored ID keeps the clock's time on its row, as before); `recordLike`, `recordCompletion` and the batched `recordCompletions` record a decision after the caller wrote the owner's row (an episode with one ID and no row records nothing); `historyIds` works out owners in batches; `removeGroupState`, `restoreGroupState` and `clearGroupStates` remove an episode's settings with its history and put them back on Undo; `downloadHolder(s)` names the ID whose completed download plays an episode; `memberIds`, `withAllAliases`, `groupTokens` and `queueIdentities` serve the queue, Smart Queue, Smart Downloads, sync and ranking; `queueRemovalIds` names the IDs a queue removal records: the removed ones and every other trusted ID of their episodes, queued here or not (a cloud sync pull keeps one queue entry per episode, so the cloud can still hold another), except the IDs of an episode that stays queued or plays; `withAllAliasesFlow`, `memberIdsFlow` and `aliasGroupsFlow` expand IDs to every trusted ID of their episodes in memory from the watched shared aliases, so download and queue indicators read an episode under the ID a screen shows. `ownerRow` gives a new history row written under another ID of the playing episode (its owner) the owner's own show (its stored row, else its catalog row, else its alias), and `keepingOwnerMetadata` keeps a stored owner row's show and episode metadata when another ID's page saves progress, so the owner row of a show switched to its feed stays under the Podcast Index show it belongs to. `showReplacementsFlow` maps each Podcast Index show a followed RSS show replaced (and the listener no longer follows) to that RSS show, for listening read by show. Like times in the group settings stay monotonic within an episode even when the clock reads earlier than a recorded decision.

## Dependencies

- Project dependencies: `:core:model`, `:core:network`.
- Libraries: Room runtime, Room KTX, Room compiler through KSP, and Gson.
- Reverse-edge rule: database must not depend on catalog, playback, downloads, designsystem, or feature modules.

## Threading / lifecycle

- `BoxLoreDatabase.getDatabase` is a process singleton created from application wiring.
- DAO operations expose suspend functions and flows; callers should keep large database work off the main thread.
- Feature modules should depend on ports or repositories rather than injecting `BoxLoreDatabase` directly.
- Completed episode ids are read in pages of 1,000 inside one transaction (`ListeningHistoryDao.getCompletedEpisodeIds`). The Flow re-reads them on any `listening_history` change. A single cursor over tens of thousands of ids failed with "Couldn't read row … from CursorWindow".
- `FolderDao.addPodcastToFolderIfExists` and `setPodcastsForFolder` do nothing when the folder no longer exists, so a link racing a folder deletion cannot violate the cross-ref foreign key.
- `BoxLoreDatabase.getDatabase` re-checks the instance inside its lock so two threads never open separate Room instances on the same file.
- Migrations run on the first open after an update, from whichever caller opens the database first. That can be the playback service (`PlaybackHistoryStore`) with no `AppContainer`, so a migration may only use the database and `:core:model` (the 38→39 seeding uses `EpisodeRecipeId` from there). The 38→39 upgrade rewrites no catalog row; on the JVM it took about 0.4 s for 20,000 catalog rows with 2–20 KB descriptions (a 240 MB database), where rewriting every row to mark it legacy had copied about 240 MB through the journal.

## Persistence & identity

- Room filename `boxlore_database` stores user data and must remain stable.
- Legacy database rename behavior preserves installs that used `boxcast_database`.
- `BriefingArtworkCompatibility` repairs legacy numeric Brief artwork references on open and on later history, queue and download writes (including cloud/backup restores). Region aliases resolve to the shared named-resource contract in `:core:model`. Only artwork columns change; progress, likes, audio, queue order and sync flags are preserved. Conditional SQLite triggers are idempotent and installed after schema migrations; schema version and table identities stay unchanged.
- Entity/table schemas and migrations are release-critical persisted contracts. Never edit a migration or an exported schema once a phone may have run it: Room refuses to open a database whose schema hash differs at the same version. Later schema changes go to a new version (v40 and up).
- `BoxLoreDatabase.builder` is the one database configuration, used by `getDatabase` and the upgrade tests. Upgrades from version 12 on run `BoxLoreDatabase.ALL_MIGRATIONS`; a version with no path fails to open with an error instead of silently erasing history, queue, downloads and likes. Versions 1–11, which predate every migration, and opening a newer file with an older build (a downgrade) still recreate the database empty.
- `EpisodeAliasProvenance.ORPHAN_REMATCH` (`orphan_rematch`) marks a phone-minted ID whose state the orphan rematch moved onto a catalog row it matched by its exact enclosure address. `EpisodeAliasProvenance.CATALOG_KEY_MATCH` (`catalog_key_match`) marks a catalog row's ID that joined an episode because a trusted alias already held its (show, key) under another ID (the episode's row was evicted and the feed read again). `EpisodeAliasProvenance.RSS_SOURCE_LINK` (`rss_source_link`) marks an RSS episode ID of the feed a Podcast Index show was switched to, recorded under the Podcast Index show as a non-owner (ownership then follows the owner rule): trusted when an old ID's trusted key is the RSS episode's key and no other RSS episode has it, or an old ID's exact audio address names it alone, ambiguous otherwise until a later link finds exact evidence. `EpisodeAliasProvenance.RSS_SOURCE_AUDIO_MATCH` (`rss_source_audio_match`) marks an old ID of the Podcast Index show, with no usable key before, that such a link settled by its exact audio address. `EpisodeAliasProvenance.CLOUD_SYNC` (`cloud_sync`) marks an ID a cloud sync pull recorded: trusted when the pulled row named, by catalog key (else by a recipe ID exactly one key of the show has), an episode this phone already holds under a trusted ID; unresolved when the phone doesn't know the episode yet. Such an alias is never the owner when it is recorded. Stored provenance and state strings are never renamed.
- `EpisodeAliasProvenance.RENUMBERED_SHOW_MATCH` (`renumbered_show_match`) marks an ID of a Podcast Index show that Podcast Index renumbered, with no usable key before (no alias, or an unresolved one under the old show), that joined one stored episode of the show it now answers as: recorded trusted under the new show with that episode's key, as a non-owner, while its history, queue and download rows keep their ID and old show ([docs/EPISODE_IDS.md](../../docs/EPISODE_IDS.md#renumbered-shows), `RenumberedShowLinker` in `:core:rss`). It also marks the trusted aliases of an old show's (show, key), the shape of a show whose catalog was read before the renumbering, moved to the new show's (show, key) with that episode's recipe ID, as non-owners. `PodcastDao.moveRenumberedFollow { … }` runs a follow move in one transaction: the caller reads both rows, merges them and writes them through `upsert` (each keeps its stored namespace) with no other writer in between; `LocalEpisodeCatalogDao.listForShow` reads the identity, title and date of one show's stored rows for that link (`LocalEpisodeLinkRow`, no descriptions), and `PodcastDao.getSubscribedRssPodcastLinkedTo` finds the followed `rss:` feed linked to a show even when an unfollowed one is linked too. DAO additions only; Room stays at version 39.
- Episode aliases, group state, the `legacy` mark and alias provenance are permanent: old local IDs (Podcast Index, phone-minted negative and recipe IDs) keep resolving through them after their catalog rows are evicted. Alias `catalogKey` values are the recipe-trimmed keys of [`docs/EPISODE_IDS.md`](../../docs/EPISODE_IDS.md).
- Package root is `cx.aswin.boxlore.core.database`.
- Ranking persistence is owned by `:core:ranking` in `adaptive_ranking_database`.
