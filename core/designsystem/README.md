# `:core:designsystem`

## Purpose

Owns shared Compose visual primitives: theme, typography, shapes, motion, loaders, image helpers, navigation chrome constants, and share-card UI. It does not own feature navigation, repositories, network clients, Room access, or business workflows.

## Public API

- `layout/BoxloreCardSpec` defines tablet card families: Hero 280–480dp, Poster 140–208dp (square artwork), Episode 280–720dp, RailItem 140–310dp, Reading and Utility 280–720dp. Minimums guide packing; narrow panes remain reachable. `boxloreCardWidth` centers the painted surface inside tight slots, and returns the original modifier on every phone layout. Existing fixed rail/cover dimensions remain within these bounds. `boxlorePosterColumns` packs the current content pane by the Poster minimum; it never changes data or ranking inputs.

- `layout.BoxloreWindowLayout` is the app-supplied window/fold model. Width classes are Compact (<600dp), Medium (600–839dp), Expanded (840–1199dp) and Large (≥1200dp); height classes use 480/900dp. Tablet layouts require both ≥600dp width and ≥480dp height, so short landscape phones retain their phone geometry. Split layouts additionally require ≥840dp and landscape. `LocalBoxloreWindowLayout` defaults to the existing phone presentation for isolated previews; the app supplies real bounds once. Pure `boxlorePaneSpec` and `foldSafeRegions` select bounded panes/contiguous hinge-free regions without touching feature data, ranking or playback. `LocalBoxlorePaneWidth` carries actual content width, distinct from full window width.

- Daily edition inherits the listener theme through solid Material 3 backgrounds and panels. `BriefingCover` displays the uncropped 16:10 image with a live masthead and an optional localized contrast scrim for the page logo; Home metadata uses a local bottom scrim. Page callers clip the lower image corners and keep content on an opaque background, without artwork fades or glass layers. `BriefingPageStatusBars` keeps system icons readable over the cover and restores theme styling on exit. Bundled WebP artwork includes seven covers each for Global, India, UK and US; `briefingCoverResource` selects Monday–Sunday from the edition date, with Monday as the invalid-date fallback. `briefingPlayerResource` keeps the fixed branded regional squares and legacy drawable names. Named resource URIs and the player resource keep file preserve playback artwork across builds.

- `OptimizedImage.fallbackUrls` and `FeedMediaCard.fallbackImageUrls` retain alternate artwork until actual load failure, rather than selecting one URL up front. `ArtworkAttempts` tries optimized then original for at most four distinct images, followed by at most one recovery attempt for a transient failure. HTTP 403/404/429 and decoding failures do not get an immediate retry. `ArtworkLoadPolicy` bounds hints to 256 entries with 30-second transient and five-minute permanent cooldowns; known successful routes can recover a failed tile across screens and sizes. Each remembered route keeps the pixel width it was requested at, so a larger image only reuses a route at least as large (or the original); a smaller copy, such as a cover chip's thumbnail, is tried only after the larger request's own routes fail. Reusing it first made larger cards randomly blurry. Foreground reentry and reconnection refresh only failed tiles; there is no polling or recomposition retry loop. Each request has an eight-second timeout. `loadArtworkBitmap` shares the process Coil cache with widgets, share cards and push artwork while propagating cancellation. Existing `URL-wWIDTH` UI cache keys and artwork dimensions are preserved. `ArtworkPrefetch.prefetch` warms Coil with the exact first request `OptimizedImage` makes on phones (same route, size and memory key) for artwork about to appear, such as the onboarding show deck; on tablets the card may measure to a larger bucket and load normally (`ArtworkPrefetchTest`). Policy and actual Compose/error/recovery regressions are JVM tests.

- `DiscoveryTabSwitcher` shares Explore and Subscriptions tab presentation: solid tonal capsule, one spring-driven selected capsule, optional icons/badges and selectable Tab semantics. Fixed and floating variants retain page-owned selection, preferences and docking. `discoveryTabSwitcherHeight()` shares text-scaled geometry with overlay clearance (48dp minimum). The moving capsule and foreground tint share a single position clock; constant label weight and no extra tab ripple avoid flashing a second selection during movement. Selection semantics and callbacks remain immediate. Indicator placement mirrors in RTL; badges hide at zero and display `99+` above 99. JVM interaction coverage runs in Home’s existing Compose/Robolectric host.

- `LocalUpdateAvailableAction` carries an optional app-shell UI action. `TopBarUtilityActions` connects icon-only Update, Feedback and Settings action segments using Material 3 connected spacing and leading/middle/trailing corners. The optional Update segment uses primary-container/on-primary-container roles and a shimmering system-update symbol; it has no nested circle and appears only when the action is supplied. Feedback/Settings click and long-press callbacks, toolbar height and shortcut placement remain unchanged. Its accessible label is **Update available**; the design system owns no update checking or installation.

- `ArtworkNavigationColors.appThemePreviewEntryId` tracks a temporary regular-page preview separately from committed entry ownership. Preview changes do not mutate saved artwork palettes; navigation commits and cancellation clear the preview.

- `BoxLoreTheme` and theme helpers such as expressive shapes, motion, typography, and dynamic color utilities. `resolveBoxLoreColorScheme` / `resolveBoxLoreChromeColors` / `darkThemeFromConfig` expose the same Appearance ColorScheme as ARGB for non-Compose chrome (home-screen widgets). Custom `theme_brand` may be a named seed, `#RRGGBB` (Material 3 palette from that seed), or `exact:#RRGGBB` (pins primary to that RGB; not recommended for readability). `Modifier.expressiveClickable` has a long-press overload (`onLongClick`) used by Downloads multi-select. Its default `ExpressivePressFeedback.Surface` keeps cards, rows and headings steady with a bounded Material ripple. Custom controls explicitly use `ExpressivePressFeedback.Control` for a 3% critically damped press response. Pass the actual `shape` to clip feedback; explicit `indication = null` opts out of ripple, and `pressScaleEnabled = false` lets a drag overlay own scale. Native Material buttons/cards keep their own handlers and indications; do not add this modifier to them. The obsolete no-op `isolate` argument has been removed.
- `CustomThemeSeeds` encodes primary and optional secondary/tertiary seeds as versioned `custom:1:...` values in the existing theme-brand key. `generatePersonalColorScheme` uses Material Color Utilities HCT/tonal palettes and coordinated color roles for both modes; existing authored/hex/preset resolution remains unchanged. `artworkSurfaceStyle` retains Pure surfaces while allowing artwork-tinted detail pages; `extractArtworkPalette` is the one artwork picker shared by podcast and episode pages, the full and mini player and Home's hero cards: `selectArtworkSeed` takes Palette's 16 swatches (default filter, so near-black and near-white are already gone), ignores any under 1% of the cover, outside HCT tone 12–92 or under chroma 8, and picks the best mix of coverage and colourfulness (share × 70 + chroma, capped at 64, × 0.3); covers with no meaningful colour have no palette, so their screens keep the listener's theme. `ArtworkPalette` carries that `seed` and the cover's mean colour (`average`). `artworkColorScheme` builds a page's scheme from the seed exactly as a custom theme (`generatePersonalColorScheme`), keeping Pure grounds. `loadArtworkPalette` / `cachedArtworkPalette` share one 96-entry process cache keyed by artwork URL between detail pages and the player. `LocalArtworkColorsEnabled` carries the saved opt-out. `ArtworkNavigationColors` captures the visible source palette synchronously at navigation, retains up to 80 entry snapshots and starts forward and Back handoffs with the departing colors, and invalidates them when the saved theme or artwork opt-out changes; `rememberAnimatedArtworkColors` eases all roles on one clock (`ArtworkColorTransitionMillis`, 350ms, the page slide's length) and retargets from the visible palette. `LocalArtworkLoaderColors` carries the loader palette: detail pages provide their synchronized page palette, and regular pages use the saved app colours from the first frame. `OnScreenArtwork` records which Coil memory-cache entry shows each artwork (the largest `OptimizedImage` copy), so `loadArtworkPalette` reads the cover the listener just tapped instead of fetching another copy. `ArtworkNavigationTheme` inherits the page’s exact animated accents and restrained neutral surfaces, including Pure overrides; playback chrome remains independent. `artworkPlayerColorScheme` is the player's scheme from the same seed through `generateBrandColorScheme`; `ArtworkMiniPlayerColors.fromScheme` gives the mini bar the scheme's primary container and Play its primary. `ArtworkShade` turns a seed or the app's primary into fixed-tone colours for words over a cover (a deep shade, light text, a bright button), each pair readable on any hue. `ArtworkDuotone` redraws a cover in two tones of one colour (a shadow at tone 8 and a highlight at tone 38, chroma up to 40 and 56, golds for dark yellows; `Neutral` is black and white) through a brightness colour matrix with a slight contrast lift (`colorFilter`, no extra bitmap), so `ArtworkShade`'s light text reads on any part of it. Its vivid pairs (`fromColor` / `fromPalette` with `vivid`, and `NeutralVivid`) keep a tone-10 shadow and lift the highlight to tone 80 in the colour's own hue (chroma up to 72), for covers whose words sit on their own scrim (Home's Marquee hero), so the art keeps its brightness. `artworkDeepShade` gives a deep but clearly coloured shade of a colour (its hue at a chosen Material tone with chroma up to 36; golds instead of olives), used for Lore card grounds.
- Shared components including `OptimizedImage` (optional `errorContent` for blank/failed art; `showLoadingPlaceholder = false` for decorative layers such as Marquee's blurred backdrop, so the logo placeholder never shows through), loaders, `PillFilterChip` (onboarding/Explore genre pills), `BoxLoreLogo` (optional `height` for hero vs chrome sizes), `RemoveDownloadConfirmationDialog` (Material 3 confirmation dialog before removing downloaded media), player-control primitives used by UI modules, floating 3+1 navigation chrome, bottom-content clearance helpers, sleep-timer chrome, and the non-dismissible `RepairProgressPopup` for app-shell foreground repair status.
- `TopBarUtilityActions` groups Feedback and Settings as 33dp-tall solid Material 3 connected action segments, adding Update when available. Settings uses the sliders (`Tune`) icon. Feedback/Settings use 20dp icons in 43dp-wide segments with press feedback; the update symbol is 22dp. Presses retain each segment's connected corners and use the existing restrained scale response without an extra rectangular ripple. The shimmer remains clipped to the Update segment. These remain action buttons rather than mutually exclusive selection controls. Foundation expands touch bounds vertically beyond the compact visual height. Screen owners retain placement, click/long-press callbacks and shortcut visibility; this component owns no scroll behavior. Home's JVM `TopBarUtilityActionsTest` covers actual pressed-corner pixels with/without Update and the click/long-press callbacks. Custom control backgrounds belong inside the press layer so the complete coloured surface contracts together with its content; native Material controls keep their own indication.
- `LocalAdaptivePlayerCompactProgress` carries the app-owned player/nav morph clock. `Modifier.adaptivePlayerOverlayOffset` reads it only during placement, moving floating feature controls down by the released player row during the shared `adaptivePlayerDockingProgress` phase. Classic and absent playback retain their placement; list/content clearance remains stable.
- Regular navigation tabs in both presentations use the current theme's `primary` accent and `onPrimary` icon color through `NavigationAccentColors`, including authored presets, wallpaper palettes and exact custom accents. Classic selected labels use the same accent. Floating Lore retains its multicolour aurora and container base, blended into the single moving indicator during draw rather than adding another selection surface. Its selected icon uses `onPrimary` before the aurora arrives, `onPrimaryContainer` at rest, and the more readable of those foregrounds during the solid-base blend; foreground selection follows the same indicator position without a second delayed color animation. Unselected icons retain `onSurfaceVariant`.
- `icon.GenreIcons`: Rich icon palette and resolution helpers for custom podcast genre tags, subscription folders, and filter chips. Maps icon keys to Material Rounded icons (`all`, `findIcon`, `defaultGenreIcon`, `iconOrFallback`, `defaultFolderIcon`, `folderIconOrFallback`).
- `icon.GenreSuggestions`: Real-time keyword-driven suggestions and fuzzy ranking helpers (`GenreSuggestion`, `ALL_GENRE_SUGGESTIONS`, `filterGenreSuggestions`, `findSuggestedIcons`, `buildFolderSuggestionsWithLibrary`, `buildGenreSuggestionsWithFolders`) for genre tagging and folder creation with library prioritization.
- `icon.GenreExactMatchResolver`: Exact case-insensitive matching (`findExactGenreIconKey`) that auto-switches folder icons in real time as the user types matching genre names or topic keywords without waiting for manual chip or grid taps.
- `PredictiveBackWrapper` peeks the NavHost (scale 1.0 → 0.9) during system Back. Its optional `backgroundColor` lets the shell keep the visible artwork palette during the peek without changing the saved app theme. Progress always returns to rest after commit or cancel so a Back that replaces the start destination (cold-start Subscriptions → Home) does not leave Home scaled down.
- Shared discovery cards: `FeedMediaCard`, `CuratedEpisodeCard`, `EqualHeightPosterGrid`, and `FeedPosterSpacing`. `FeedMediaCardPresentation.Default` retains the existing outlined presentation. Explicit `ExpressivePoster` and `ExpressiveFeatured` variants use native clickable cards with a three-line title-only foot that vertically centers shorter titles and grows with font scale. Posters use solid surface-container cards with 24dp corners, 14sp/20sp text, and restored 16dp lower artwork corners. Featured cards use a title-first split composition on solid tertiary-container: a 16sp/24sp three-line title and standalone 24dp forward arrow at the start, with artwork occupying 44% of the width (capped at 176dp) and running flush to the end edge. A sweeping 72dp artwork corner and asymmetric 28dp/12dp outer corners define the silhouette; the composition mirrors in RTL. The arrow belongs to the same native card action, 12dp below the reserved title area. Featured artwork omits promotional overlays. Their normal-text height is 152dp; enlarged text grows the layout. `FeedMediaCardSkeleton` shares the loaded layout and a measured three-line paragraph, covering nonlinear font scaling and keeping placeholders equal to loaded cards. `DiscoveryExpressiveTheme` scopes expressive Material motion while inheriting the existing color scheme, typography, shapes and appearance preferences; it does not change the application theme.
- `ProgressiveSearchScrollLogic` decides when a progressive Find-a-show list should pin to the top (query change, new top hit, or Matches header). Used by onboarding search and Explore Find-a-show; Ask anything does not use it.
- `LazyListKeyPolicy` provides safe deduplication and collision-free key generation for LazyColumn, LazyRow, and LazyGrid lists, preventing `IllegalArgumentException: Key was already used` crashes from duplicate backend feeds or search hits.
- `share.ShareManager` for composite share cards and the system share sheet; emits glossary `share_content` via `:core:analytics`. `ShareBottomSheet` presents a clear content preview, a switch-style timestamp option, a primary artwork share action, and separate link/story actions.
- Episode share links come from `ShareManager.episodeShareLink` (the address and whether it opens the show; `episodeShareUrl` is the address alone), which asks `ShareManager.episodeShareTargets` (an `EpisodeShareTargetSource` from `:core:model`; the app installs one that reads aliases and registers the episode, with a short wait) which ID and show the link names. When the installed source fails, the episode's own fields decide. `shareEpisode` builds its text and card after that lookup, off the main thread, and leaves out the start time or clip when the link opens the show. `EpisodeShareLinkTest` covers episode and show targets, the fallback for a failing source, and `t`/`start`/`end` beside `&show=`. The sheet's Copy link takes the shared `episode` and copies through `ShareManager.copyEpisodeLink` in the share scope, so closing the sheet doesn't cancel it; podcast links and callers that pass no episode copy at once as before. The sheet's layout is unchanged.
- `ShareManager.shareImage` shares a card a screen rendered (Listening history's story share card) with its text: the PNG is written off the main thread beside the other share cards in the cache, cleared after a day, and the text goes alone if it can't be written.
- `share.ShareCardRenderer` builds the share-card bitmaps used by `ShareManager`. Stories and square artwork separate episode/show details from a compact “Listen on” label and upright boxlore wordmark.
- `echo.EchoCharacter` (added 2026-10-16) is the boxlore mascot, shared by onboarding (Welcome and the Echo conversation), Account & sync and the app's library import. It plays a named sequence from `assets/echo-character/manifest.json`: steps that play once, then an optional loop, each step a still (`front-rest`, `t1-rest`, the account outfits…) or a motion clip. Clips are short MP4s with colour, alpha and a glass mask stacked in one frame (384px wide, one keyframe, 24 fps), decoded off the main thread with `MediaCodec` (`EchoClipFrames`), a few frames ahead, the next clip prefetched 600ms early and a 120ms cross-fade between clips. Frames playback has moved past are released for reuse, except the clip's last few, which stay ready for the next loop round. Echo's face is two LED eyes drawn in code on the screen glass: each clip frame carries a tracked screen box, and the glass mask lets props pass in front of the eyes. `EchoIdle` scripts move the eyes (180ms darts, 150ms blinks) once a sequence rests. With `stageColor`, Echo stands on a Cookie9Sided stage 1.14 times its resting height, centred on its body, so the stage always follows Echo. Accent parts take a calmed tone of the theme's primary (`tintEchoAccents`); with `accents = EchoAccents.Custom(parts, face)` a scene keeps Echo's own indigo (`EchoAccents.Original`) or recolours the accents vividly to a colour that suits its background (`recolorEchoAccents`, keeping each pixel's shading), with the face lit in another hue. A clip can carry a face script (each beat's face and gaze from its share of the clip on), frames where the eyes blink, and lens frames: while the detective holds a magnifier over the screen, one big eye shows through the glass (the glass band then holds the glass less its glints, so they stay on top). `rememberEchoCharacterSpec` reads the manifest once per process; screens use its outlines (`reaches`) to place Echo. With animations off, or `LocalEchoMotion provides false` (tests), it shows the rest pose so screens can go idle. The assets take about 5.9 MB: the nine onboarding clips (1.4 MB) and fifteen story clips with their rest stills (4.3 MB, added 2026-10-31 for Listening history's monthly story: hello's wave, an hourglass, a trophy, a celebration, morning, daytime and night outfits, and true crime, tech, news, history, fiction, comedy, science, business and health outfits). A sequence that is one picture (a single step, no clip, no loop; `EchoCharacterSpec.isStill`) shown without an idle script draws once: its frame clock never runs.

- boxlore classic uses electric violet with quieter blue and teal supporting accents, cool neutral surfaces and complete fixed-color roles. ## Dependencies

- Project dependencies: `:core:model`, `:core:analytics`, `:core:prefs` (lettering axis + shared Google Sans Flex `Typeface` loader).
- Libraries: kotlinx.serialization JSON (the Echo manifest), Compose Material, MaterialKolor’s public, platform-independent Material Color Utilities JVM port (keeps the current Android SDK requirement), Material icons, graphics shapes, Coil, AndroidX activity/core, smooth corner rect, and coroutines.
- Reverse-edge rule: designsystem must not depend on catalog, network, database, playback, downloads, or feature modules.

## Threading / lifecycle

- Compose UI work runs on the main thread.
- `BoxloreDialog` retains one native dialog and moves the same content between phone and tablet frames during resize or folding. Content-owned drafts and scroll state survive layout changes while owner content and callbacks stay current; native phone dimming is restored on return from the tablet frame.
- `boxloreCombinedClickable` keeps labels and main actions explicit, grouping optional role/double-click/haptic behavior in `BoxloreClickOptions` and an explicitly supplied source/indication in `BoxloreClickInteraction`. Omitting the interaction preserves native phone behavior and tablet feedback; an explicit null source or indication stays null. Secondary-click gesture ownership remains with the deepest enabled target and resets when input is cancelled.
- Coil performs image loading on background dispatchers. `OptimizedImage.proxyWidth` and `optimizedImageUrl(width)` are pixels (clamped to 10–2048); proxy/CDN dimensions and Coil decode dimensions use the same value without an extra density/quality multiplier. `OptimizedImage` keeps its solid fallback underneath the painter through the entire success crossfade; Coil success does not remove that backing before artwork becomes opaque. Error content still draws above it. Loading and missing/failed artwork use the shared `ic_boxlore_app_mark` B-and-microphone vector, centered at 64% of the artwork bounds and tinted with `onPrimaryContainer`; missing/failed art retains the subtle expressive shapes. The mark is decorative, so card/artwork descriptions remain the accessible identity.
- `m3Shimmer` is a draw-only modifier node: a screen of skeleton blocks adds no composition work. Inside a `ShimmerScope` each block follows the shared clock; outside one, a block runs its own infinite-animation clock, which tests treat as idle. That clock follows the system animation speed and holds still while animations are off (`HomeShimmerReducedMotionTest`).
- `ShimmerScope` shares one linear, draw-only loading clock across a feed and stops it when loading finishes. Visible skeletons animate even while their navigation entry is still CREATED; the Compose window lifecycle pauses frames in the background. The published phase keeps a stable State reference across loading transitions so cached lazy-item draw modifiers resume the sweep instead of retaining the stopped value. The horizontal shader moves over a stationary full-block rectangle, with alpha-correct highlights and matching transparent edge colors. Its 1600ms two-width travel starts a quarter-cycle into the sweep so the first loading frame already has a highlight, and keeps the sweep visible through the cycle without a trailing idle interval or a hard rectangle edge through tall placeholders.
- ColorScheme resolution is remembered for theme inputs and resource configuration changes.
- `ThemePresets` defines sixteen complete themes: the original ten Colorful palettes, Minimal Paper/Graphite, and Bold Voltage/Arcade/Solar/Cobalt, each with its own light/dark background, tonal surface hierarchy and authored primary/secondary/tertiary accents. Collection metadata is presentation-only; every palette is checked for readable text across accent and surface roles in both modes. Stable `preset:*` keys use existing `surface_style` and `theme_brand` preferences. `resolveFixedThemeColorScheme` shares resolution with Appearance previews and app/widgets. Theme mode remains independent. Personalising an accent or enabling wallpaper colors retains the chosen preset background; choosing another background retains the existing background-selection behavior. Existing seed/custom/exact colors and legacy mode locks remain supported.
- The theme is applied by `:app` and feature composition roots; this module owns no application-scoped repositories.

## Persistence & identity

- No user data, database files, DataStore names, or SharedPreferences files are owned here.
- Resource names are app-internal UI contracts and should be changed with normal Android resource migration care.
- Echo sequence ids in `assets/echo-character/manifest.json` (`welcome`, `onboarding-*`, `account-*`, `import-*`, `story-*`) are called by name from `:feature:onboarding`, `:feature:settings`, `:feature:history` and `:app`; each caller has a test that its ids ship in the manifest.
- UI typeface: bundled **Google Sans Flex** variable font (`res/font/google_sans_flex_variable.ttf`). Default **ROND = 100 (Round)**; Appearance → Lettering can switch Crisp (0) / Soft (50) / Round (100) via `FontRoundness`, `LocalFontRoundness`, and `BoxLoreTheme(fontRoundness=…)`. `GoogleSansFlexTypeface` caches native faces by weight and axes (`ROND`, `opsz`, optional `wdth`); `Typography.kt` wraps each resolved face in a Compose `FontFamily` so Android skins cannot collapse Material typography weights. `GoogleSansWeight` centrally maps app emphasis to the lighter 400/400/500/600 scale. `rememberGoogleSansFamily()` is the shared helper for explicit weighted UI. Roboto Flex paths (`RobotoFlexFamily`, `LogoFontFamily`, `robotoflex_variable`) are unchanged. `DisplayFonts.kt` adds `UnboundedFamily` (ExtraBold) and `SpaceMonoFamily` (regular, bold) through the same Google Fonts provider (now `internal` in `Typography.kt`), nothing bundled; they are display faces for surfaces that deliberately step outside the app's type (the show deck's Prism card) and never for regular UI text. Shared connected chips: `ConnectedOptionSelector` (Appearance, Library history period/status filters; optional `contentPadding` / `labelStyle` for dense 3-up labels). Content region uses `RegionSegmentedSelector` (trigger plus sheet list of 11 storefronts, onboarding) and `ContentRegionPickerSheet` (the sheet alone, opened from a settings row). `ContentLanguagesSheet` (29 Oct, D9) is the languages sheet: "Include English" first (off only when every pick is in `ContentRegions.ENGLISH_OFF_LANGUAGES`; disabled with the reason otherwise, wording in `includeEnglishSupportingText`, `ContentLanguagesSheetCopyTest`; with English off it says the smaller pool makes recommendations match the listener's taste less closely, then that English fills thin results), then suggested-for-country and other language chips with an "N of 4 picked" count; with English off its slot takes a pick. SIL OFL 1.1 text: [`licenses/GoogleSansFlex-OFL.txt`](licenses/GoogleSansFlex-OFL.txt).
- Lettering roundness is mirrored in `boxlore_theme_fast_cache` key `font_roundness` (owned by `:core:prefs`) so share cards / Auto collage can read it without a Compose tree.
- `BoxLoreNavigationBar` owns the selectable navigation presentation: a solid Material 3 floating 3+1 shell (Home / Explore / Library pill plus Lore action, with one persistent active indicator tracking all four tabs) or the classic four-tab bar. Its optional `compactProgress: State<Float>?` is supplied by the app alongside the mini-player's shared animation: Floating eases labels into icons and moves the same Lore action into a fourth pill slot during contraction, reserving its former 52dp trailing slot before playback docks. A single selection surface sits above the neutral pill/Lore backdrops and below their actions. It travels directly between all four targets in 240ms and morphs from the external Lore circle into the compact fourth-slot capsule. Retargeting starts at its current position and heads toward the latest tab without retaining travel in the previous direction; hiding it never retargets it to Home. Floating actions use ripple-free selectable semantics and subtle icon/label press scaling, so touch feedback cannot paint a second highlight. Solid high-container surfaces, a fine outline, restrained elevation, crossfading filled/outlined icons and press scaling keep both states consistent. Pill width, 16dp edge insets, and `AppFloatingNavigationActionGap` (14dp) stay fixed; the compact Lore target is 48dp. Placement follows layout direction, and selection semantics / spoken labels follow each persistent action. Progress is clamped and read during measurement, placement and graphics layers; neutral Lore elevation follows the shared contraction without per-frame composition. Classic ignores compact progress. Lore uses a subtle icon settling animation after initial content is ready. Lore restores the original blue/pale-blue/violet/red/gold/green multicolour aurora inside that same selection surface, with its original restrained 0.44 colour opacity and a softer broad highlight. Colour strength follows the actual indicator position with an eased blend, including interrupted tab changes, so no separate Lore highlight is painted. Cached diagonal/radial brushes and draw-only phase reads keep its 20-second round trip out of per-frame composition; the original sweep eases smoothly through both turnarounds, pauses while Lore is unselected and resumes from its retained position, and the parent selection shape clips both the external circle and compact capsule. `NavigationChromeMetrics` and `appBottomChromeContentPadding()` keep app and feature overlays clear of the selected chrome and its matching mini-player geometry.

Bitmap callers can choose a shorter per-attempt timeout while retaining outer cancellation; successful-source callbacks identify the original source rather than its transport route.

## Testing notes

- `EchoCharacterModelTest` checks that every manifest frame ships as a WebP with its screen inside the frame and every clip as an MP4 with its screen tracked in every frame, and covers blinks, the LED grid (whole pixels from 3px apart), decode sizes, two mirrored eyes, the accent tint, the vivid recolour, Echo's own colours, and the story clips' face scripts and lens frames. `EchoMotionModelTest` covers sequences that play once and rest, loops, rejecting sequences with nowhere to rest, clip timing, face scripts with blink frames, and unpacking a stacked frame (colour above, alpha below, limited-range chroma). It also checks which story sequences are stills.

- TabletFeaturedRow packs a two-column feature beside later posters with caller-supplied spacing. Card-width callers may choose a narrower family maximum; tight slots retain their extent while centering the bounded surface. Actual shell mini-player visibility supplies tablet footer clearance. Brief artwork scaling is configurable while existing callers retain Fit.

- `BoxLoreNavigationRail` reuses the phone destinations, selection-index/retargeting functions, accent colors and Lore aurora. One icon selection surface travels between all four actions; labels remain on a readable neutral surface. Icon tints follow the moving indicator in the draw phase, so the rail does not recompose on every animation frame. Shell-provided rail/player-pane flags keep feature overlays clear of the actual chrome. Pure placement tests cover taskbar and docked-player clearance for both saved navigation styles.

### Upright brand wordmarks

- Extended brand wordmarks and the LORE navigation brain are upright. Share cards use the plain upright wordmark at 280px wide. Stories stack “Listen on” above it in a centred signature below the content, clear of bottom story controls. Square message cards place the label and wordmark in one centred footer row with a 96px bottom inset. Labels retain a 12px size when the full export is displayed at 360px wide; artwork and title remain the main focus.

The toolbar action segments use a compact 43 × 33 dp visual size. The available-update segment has a restrained shimmer across its surface.

Expanded tablet modals use solid, inset-aware dialogs up to 640dp within one fold-safe region; phone calls delegate to the unchanged Material sheet. Finite tablet sheet forms can scroll while lazy lists own their viewports. Owners with custom Hidden confirmation supply the matching `centeredDismissAllowed` policy; Engagement defaults to blocking implicit dismissal, and the current ordinary survey/review states opt in explicitly. Shared custom-control feedback adds tablet hover/focus and secondary-click long-press ownership. Artwork upgrades use measured pixel buckets, retain sufficient larger targets and preserve phone keys. Tablet artwork waits while a hidden pane gives it 1px or less, keeps its measurement across phone/tablet changes, and loads at the requested size when its layout has room but the artwork sizes itself. Window-size fallbacks exist only for isolated previews/tests.

The Material BasicAlertDialog override delegates directly to the default host on phones and flat windows. On folded tablets it hosts the unchanged Material content in the shared safe dialog frame, including date pickers. Raw dialog owners use `BoxloreDialog`; their security and dismissal policies remain explicit. All tablet portal frames cap at 640dp; ordinary alerts retain Material's 560dp maximum.

TabletFeaturedRow measures neighboring posters before applying the same height to the feature. The shared poster-height helper sums separately rounded artwork, measured text and padding pixels. AdaptiveOverflowRow measures native chips, packs the available width and uses a horizontal fallback if required controls cannot fit; features own labels, selection, callbacks and overflow menus.
