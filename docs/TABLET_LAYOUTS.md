# Tablet and foldable layout implementation

Status: all six phases and the requested tablet visual refinements are implemented and verified locally. The final installed-build interaction walkthrough remains incomplete.

## Scope and preservation

Phone geometry takes priority. The frozen 66-image phone matrix includes 360×800, 412×915 and 800×360dp, light/dark. Layout changes must pass exact dimension and ARGB equality; baselines are never refreshed. The matrix is a local check that ordinary unit-test and CI runs exclude. The phone fixtures compose each screen, and for the shell captures a static navigation bar and `MiniPlayerV2`, directly. They do not run `BoxLoreAppRoot`, `TabletAppShell`, `RetainedPlayerPresentation` or `PlayerSheetScaffold`, so phone shell wiring, player-sheet expansion and retained player state are covered by JVM tests, not by these images. Ranking, playback, storage identities and route attribution retain their existing owners.

| Family | Tablet packing minimum | Maximum surface width | Aspect / behavior |
| :--- | ---: | ---: | :--- |
| Hero / feature | 280dp | 480dp | Feature matches poster height; carousel prefers 320dp, compact body in short tabletop |
| Poster / show | 140dp | 208dp | Existing square artwork/title foot; legacy fixed-height previews stay intact |
| Episode | 280dp | 720dp | Existing horizontal row/card layout |
| Rail item | 140dp | 310dp | Existing fixed dimensions, including 310dp mix and 260dp Brief chips |
| Reading | 280dp | 720dp | Natural text height; Lore deck retains its smaller 520dp cap |
| Settings / utility | 280dp | 720dp | Settings detail column; persistent category pane when ≥672dp fits; Account 600dp, Echo 420dp |

Height classes are compact below 480dp, medium from 480–899dp, and expanded from 900dp. Orientation is landscape only when width exceeds height. The Activity shell collects window dimensions and WindowInfoTracker folds once, converts hinge pixels to physical dp once, and supplies immutable pane bounds to features. Separate survey and sign-in portals consume that same Activity snapshot. Configuration dimensions are retained separately for exact legacy phone tiers.

At 1280×800dp with an open context, the 80dp rail leaves a 710.4dp primary pane, a 16dp gap, and a 473.6dp context pane. At 1600×1000dp the context caps at 520dp and the primary grows to 984dp.

Minimums guide grid packing rather than forcing overflow in narrow panes. Compact specs preserve the complete caller constraints. Surface bounds work inside tight `fillMaxWidth` slots and center the painted child. Controls, badges and artwork previews inside a card inherit its family; they are not additional independently sized cards.
