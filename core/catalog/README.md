# `:core:catalog`

## Purpose

Owns catalog orchestration: Podcast Index access through `PodcastRepository`, subscriptions, chapters, transcripts, content catalog (v3), cross-promotion, consent helpers, install-referrer handling, backup and restore, and shared dependency bridges used by workers and services. It does not own playback, download workers, Compose UI, Room schemas, RSS internals, or ranking model storage.

## Public API

- Both episode-mapping paths ignore blank episode art before falling back to `feedImage`, retain show art separately and normalize surrounding whitespace/HTTP. Feed mappers also ignore blank `artwork` before `image`. `ArtworkMappingTest` covers blank values and signed artwork parameters without live API calls.

Failed consent writes keep activation off, and local notification flags prevent a failed revoke from implicitly re-enabling after restart. RSS sync isolates each feed and runs alongside PI sync; the source adapter explicitly implements every catalog operation.

- `SubscribedEpisodeCatalog` routes the shared local catalog contract by podcast ID to the PI or true RSS adapter. Shared negative IDs from a source switch resolve to the active subscription rather than a retired PI compatibility row. Foreground refresh, Home tips, Smart Downloads freshness, auto-download discovery and push hydration support RSS-only shows without PI lookups or required promotion.
- RSS notification activation requires explicit public-feed disclosure acceptance through `setNotificationsEnabled(..., acceptRssDisclosure = true, disclosedFeedUrl = savedUrl)`. `DeviceRssNotificationConsent` stores only URL fingerprints in `noBackupFilesDir`; changed URLs, restore and remote cloud settings cannot supply acceptance. Canonical `rss:` IDs require disclosure even with stale source metadata. Refused or revoked activation also removes this device's old registration; a library cleared during acceptance cannot publish a deleted show. Notification settings remain independent of auto-download. The shared checker receives only explicitly accepted public feeds. `TrackedPodcastRtdbLogic.topic` maps `rss:` to FCM-safe `rss_` while retaining canonical IDs in payloads. JSON/cloud RSS restore retains the original saved show ID across redirects.
- RSS topics and per-device registration keys include a SHA-256 hash of the exact trimmed accepted URL. `DeviceRssNotificationRegistrations` keeps an atomic publication/cleanup journal in `noBackupFilesDir`, containing fingerprints and keys rather than URLs. Activation fails closed if the journal cannot be saved. `RssNotificationReconciler` awaits both RTDB and FCM acknowledgement, retains active entries and failed cleanup obligations, and retires old URL scopes or deleted/disabled shows. Live RTDB rules refuse whole-node deletes, so cleanup keeps the node and removes only its `feedUrl` child, which the checker needs to poll an RSS scope. The rules refuse that delete only when no node exists for the key (for example a legacy key this device never published), so a refusal still unsubscribes the FCM topic and clears the journal entry; any other failure keeps both. Migration scans disabled and unsubscribed canonical RSS rows too, removes legacy device keys/topics, and rejects restored notification flags without local consent. `canPresentEpisodeNotification` verifies the current saved URL, subscription, enabled flag and device-local acceptance.

- `PodcastRepository` coordinates Podcast Index calls, recommendation endpoints, curated vibes, home bootstrap, similar episodes (with content languages), content catalog/v3, user feedback submission (`submitFeedback` transmitting categorized feedback, repro steps, optional email, and diagnostics to proxy), and RSS delegation. Canonical `PodcastEntity.toPodcast()` mapper standardizes entity conversion across data and feature modules, with module-boundary isolation between `:core:catalog` and `:core:rss`. Subscribed PI shows whose local catalog is **ready** (`LocalEpisodeCatalogPort.isReady`) serve list/search/`getEpisode` from Room only. Unsubscribe stamps a 14-day TTL; that catalog stays on disk but is **not** ready, so unsubscribed reads keep today’s PI pages plus cached extras merge. True `rss:` rows are unchanged. `getEpisodes` uses a bounded window (200), not `getAllNewest`. Followed shows' catalog refreshes never read a Podcast Index list: new episodes take recipe IDs in `:core:rss`. `loadPiEpisodesForSupplement` is the Podcast Index list feed-only extras (`EpisodeSupplementPort`) are compared with: up to 1,000 newest episodes from `episodes/match` (match fields only), falling back to the oldest page (at most 100) when that route fails, returns nothing, or its `useEpisodeMatchBaseline` off switch is set. It is strict, so a failure of both stops the extras refresh instead of comparing the feed with an empty list. Its callers are the show page's "Missing episodes?" refresh, the legacy subscription sync and push paths without a local catalog, and the restore of extras opt-ins; they stay until show pages read feeds for every listener. Full pages keep the 100 cap. `getEpisode` sends a recipe-range ID (`[2^52, 2^53 − 1]`) that no local row holds to `/v2/episode` (with the show when a caller passes `getEpisode(episodeId, showId)` and the show is below 2^52) and never to the v1 Podcast Index lookup; the episode keeps the ID asked for and carries the recipe ID and catalog key. A `needsFeed` answer, a 404 or an error is not found. Podcast Index IDs keep v1 `/episode`. `invalidateEpisodesCache` drops the 5-minute PI page cache for a feed (Podcast Info pull-to-refresh). `PodcastRepository` also owns the `/v2` client (`apiV2`, a `BoxLoreApiV2` built on first use): same base URL and the same cached OkHttp client as `api`, so the process keeps one HTTP cache. Tests can pass `boxLoreApiV2` the same way they pass `boxLoreApi`. `getEpisode` is its only caller so far. In-memory caching and pagination safety are managed by `PodcastRepositoryMemoryPolicy` (`clampPageLimit` caps requests to 100, and `TimedLruCache` bounds cache entries with LRU and TTL eviction to prevent OutOfMemoryError).
- `syncSubscriptions` (`POST /sync`) is PI-only. `SubscriptionForegroundSync` sends it the shows that are **not** catalog-ready and have no saved HTTPS feed address, plus the shows whose own feed failed this pass. The PI ids go out in chunks of 20 (`PI_SYNC_CHUNK_SIZE`), at most two calls at a time (`PI_SYNC_PARALLELISM`), because the API serves only the first 40 ids of a call: whole-library callers (Smart Downloads, backup restore) used to lose every show past the 40th. A failed chunk drops only its own shows' tips. Ready ids contribute the Room newest tip; opted-in not-ready ids contribute the cached extras tip. Live feed freshen stays on `SubscriptionForegroundSync`. `getEpisodeWindow` is the bounded Smart Queue / Auto entry (never `getAllNewest`).
- Show search: legacy `searchPodcasts` / `searchPodcastsWithCorrection` keep calling `GET /search` (hybrid). New clients use `searchPodcastsTypeahead` (`GET /search/typeahead` / Meili) and `searchPodcastsGrouped` (parallel typeahead + hybrid → Matches / Also found). Concept search uses `searchSemanticGrouped` / `searchEpisodesSemantic` (`GET /search/semantic`: one CF embed → Qdrant podcasts + episodes; additive `feeds` + legacy `items`).
- `logic.mergeShowSearchResults` dedupes Meili vs hybrid by id / itunes / feed URL. Missing/generic typeahead genres are filled from matching hybrid results when their known genre agrees; title-only matches and conflicting genres are not enrichment evidence. Existing catalog identity, other metadata, order and grouping stay unchanged.
- `mapRegionForBriefing` maps content regions to briefing markets (`us` / `in` / `gb` / `global`; legacy `uk` → `gb`) via `ContentRegions.briefingMarket`.
- `SubscriptionRepository`, `ChapterRepository`, and `TranscriptRepository` expose catalog-adjacent data operations. `ChapterRepository` supports remote JSON, local file paths, and show note description parsing (`hasChaptersInDescription`, `parseChaptersFromDescription`). `TranscriptRepository` supports remote SRT/VTT and local file paths. Offline persistence and file retrieval for downloaded episodes are modularized in `ChapterOfflineStorage` (`saveOfflineChapters`, `getOfflineChapters`, `deleteOfflineChapters`, `hasOfflineChapters`) and `TranscriptOfflineStorage` (`saveOfflineTranscript`, `getOfflineTranscript`, `deleteOfflineTranscript`, `hasOfflineTranscript`). Normal `updateLatestEpisode` calls never replace a newer Room tip with an older item (`LatestEpisodeTipLogic`); same published date does **not** replace or badge. A successful full publisher-feed ingest passes `publisherFeedAuthoritative`, allowing the real feed tip to replace a newer PI cross-promo or same-date different identity. NEW is still set only when `publishedDate` is newer. Subscribe recovers a missing HTTPS `feedUrl` via `GET /podcast` (daily retry also runs in launch sync). For catalogue notification subscriptions, `SubscriptionRepository` writes RTDB `tracked_podcasts/{podcastIndexId}` with `title`, `imageUrl`, and an HTTPS `feedUrl` when a Room tip exists. Live RTDB rules allow those three keys only. The checker selects RSS whenever that URL is present, independently of Missing episodes?; it seeds `lastRssKey` quietly unless the newest RSS item matches a PI episode different from the saved `lastEpisodeId`. Turning catalogue notifications **off** removes the `feedUrl` child. Pure RSS uses the journaled per-device URL scopes described above. Unsubscribe sets a 14-day TTL on the local catalog (no CASCADE wipe), records an `unsubscribedAt` tombstone timestamp, and marks `isDirty = 1` for delta sync; resubscribing resets `unsubscribedAt = 0` and sets `isDirty = 1`. Show settings updates (notifications, custom genre/icon, auto-download, skip intro/outro, playback speed) mark the show `isDirty = 1` for cloud sync. `updateCustomGenre` applies user-defined genre overrides and custom icon keys for subscribed shows; unsubscription clears any custom tag/icon overrides and resets to original catalog genre.
- `SubscriptionForegroundSync` refreshes subscribed latest episodes (`syncSubscriptions` in chunks of 10). Cold start from Home still waits 2s for first paint; **Subscriptions appear** call `requestRefresh()`. Each pass starts with `sweepExpired` so unsubscribed catalogs past the 14-day TTL are deleted. PI `/sync` runs for shows that are not catalog-ready. Every subscribed PI show with an HTTPS `feedUrl` refreshes the local catalog (HEAD/quiet skip for ready rows; not-ready rows force the repair GET; one-time PI rematch only while `needsFullBackfill`). Missing HTTPS URLs are recovered via `GET /podcast` at most once per day, with bounded concurrency; one failed recovery does not abort the rest of the pass. A show whose own feed failed this pass is handled after the feed reads (`DirectFeedRecovery.recover`): when the failure says the saved address looks dead (`RefreshOutcome.Failure.addressGone`: 401/403/404/410/451, no such host, a failing certificate, or not a feed), `DirectFeedRecovery.recheckGoneFeedAddress` asks `GET /podcast` for the server's confirmed address at most once per day per show (the lookup counts only once the server answers); a different HTTPS address is read at once and saved only when that read works; shows still failing take their latest episode from `/sync` through the ordinary save, which never replaces a newer tip. A feed that moved for good (`RefreshOutcome.Success.movedTo`) has its new address saved. Never for `rss:` shows. `FeedFixToggles` (`addressRecheck`, `syncFallback`, `movedFeed`) are the app's PostHog kill switches; each stays on without an answer. `PodcastRepository.rolloutSwitches` (`RolloutSwitches`) carries the v2 build's switches from the app: `feedFirst` (show pages read the show's own feed instead of the server's list; off by default, and the app fixes it per process), and `upgradeRepair`, `addressCheck` and `v2Discovery` (on by default, and the app uses the last saved answer while PostHog is starting; off pauses the upgrade repair or the daily address check without marking them done, or sends discovery back to the v1 routes). Nothing in this module reads them yet. Automatic foreground feed work selects at most 10 due shows per pass, rotates past failures to prevent starvation, prioritizes the visible show, and caps concurrency at 2. Ready feeds share the RSS layer's persisted six-hour cooldown. The 15-minute timer pauses outside the foreground and leaving foreground cancels its in-flight automatic pass; the five-minute pass cooldown still coalesces repeated screen requests. A successful persist emits `directFeedRefreshed`. Subscribe calls `requestCatalogIngest` on the same application scope so the first publisher-feed persist is not cancelled when Podcast Info is popped; it ignores `requestRefresh` cooldown / in-flight gates. `catalogIngestFinished` emits when that one-shot ends (success, skip, or failure). The same pass patches RTDB `feedUrl` for notifying HTTPS shows. `:app` starts it after onboarding; Library `onScreenResume` calls `requestRefresh`.
- `LegacyRssRepair` runs once after onboarding for pre-fix OPML rows when enabled by the app-shell build/install gate. It fetches each subscribed `sourceType=rss` feed and accepts only an exact Podcast Index feed-URL variant or podcast GUID; title/author/artwork are never match inputs. Rows with `linkedPodcastIndexId` are skipped because they represent an intentional RSS-source choice. URL/GUID conflicts, lookup failures, active target subscriptions, or incomplete local catalogs leave the RSS row untouched. Successful rows adopt the PI id while retaining RSS episode ids, journaling DataStore id references for crash-safe completion, restoring notification routing for shows that had alerts enabled, and clearing any recommendation cache seeded by the old id. A pass starts only when an eligible row and connectivity are present, publishes `inProgress` for persistent app-shell status UI, and is admitted by a process-local one-shot gate. Three consecutive transient lookup/inspect failures stop the remaining sequential work. Fresh installs can persist the completed marker without starting a pass or showing progress. Once a pass settles without a pending ID transaction, its version marker is written even if individual feeds had transient failures, preventing foreground/banner loops; only a process killed mid-transaction can resume from the pending journal on a later launch.
- `content.ContentOrchestrator`, `ServerGroupedSectionProvider`, `ContentContextEngine`, and related content contracts assemble discovery slates from catalog/v3 (no live `content/sections/v1` client).
- `content.CuratedMoods` is the shared catalog of curated-mood IDs/titles used by Home daypart rails and Explore For You chips (`getCuratedVibe`).
- `backup.LibraryBackupManager` imports and exports library data, OPML, listening history, ranking backup payloads, and global prefs including `contentLanguages`, `subscriptionSort` (may be `Manual`), optional `subscriptionManualOrder`, optional `subscriptionFolderSort`, optional `subscriptionIntraFolderSort`, optional `subscriptionFolderManualOrder`, optional `autoOrganizeFolders`, optional `homePinnedPodcastIds`, optional `sameShowQueueOnly`, optional `homeShortcutsInLibrary`, optional `widgetAppearance`, optional `exploreDefaultTab`, optional `subscriptionsDefaultTab`, optional `subscriptionsTabStyle`, optional `navigationStyle`, and optional `fontRoundness`. JSON restore preserves each valid historical `subscribedAt`, custom genre overrides (`customGenre`, `customGenreIcon`), subscription folders (`SubscriptionFolderBackup`), and suppresses new-subscribe ranking feedback; missing/future timestamps fall back to import time. History restore preserves manual/bulk completion provenance while sanitizing legacy Gson-null strings. RSS/OPML restore rethrows coroutine cancellation and treats other failures as skippable. OPML import matches Podcast Index first (feed URL variants, same-title / same-feed search, then a publisher-feed peek for redirected URL + podcast GUID) and creates a true `rss:` row only after those identity lookups settle as not found. Transient PI URL/GUID/search failures defer that feed rather than silently creating an RSS subscription. Every imported PI subscription with an HTTPS publisher `feedUrl` now receives a bounded direct-feed ingest immediately, including old JSON backups whose optional `directFeedOptIns` is absent/null and OPML rows resolved to PI. Incoming **v6** `directFeedOptIns` remains a compatible explicit URL override; PI `/sync` handles only imported PI rows without a usable publisher URL, and true `rss:` rows use `refreshCatalogIfNeeded`. Settings → Add RSS is unchanged (always `rss:`); null/blank Gson `podcastId` / `feedUrl` rows are skipped. Older backups without the Manual-order / pin lists / folder lists still parse; Manual with a missing id list seeds from the current Smart list on first use.
- A JSON import links each restored RSS show that replaced a Podcast Index show (`linkedPodcastIndexId`) with the history restored under that show (`RssPodcastRepository.relinkSwitchedShow`, after the history import). The backup carries the link but no episode aliases, so only exact audio addresses prove an episode there ([`docs/EPISODE_IDS.md`](../../docs/EPISODE_IDS.md) §5).
- JSON export (version 6) writes subscriptions with their per-show settings, folders, listening history (progress, completion and likes), global prefs and the ranking backup. It leaves `directFeedOptIns` empty because restore derives publisher-feed refreshes from each subscription's HTTPS `feedUrl`; the Settings export summary names only these sections. Subscriptions are serialized from `PodcastEntity`, so `backup.LibraryBackupFieldPolicy` keeps the Room v39 feed identity and address columns (`epNs`, `feedUrlSource`, `feedUrlCheckedAt`, `transportUrl`, `previousFeedUrl`) out of the export: the format stays as it was, and `transportUrl` is never exported. Import is unaffected because restore maps subscriptions to `Podcast`. OPML export titles the file `boxlore subscriptions`.
- Android Auto browse labels (`auto_*` strings) live in this module's resources and are read by `:core:playback`. `auto_app_name` is the browse root title and stays `boxlore`, matching the launcher label.
- `backup.LibraryBackupFolderLogic` maps `SubscriptionFolder` to `SubscriptionFolderBackup` and restores folder definitions, memberships, and metadata.
- `SharedAppDependencies` and `SharedAppDependenciesHolder` expose application-scoped instances to workers and services (including `userSyncCoordinator`).
- `InstallReferrerManager` parses Play Install Referrer deep links and exposes optional `onInstallReferrerResolved` (channel + raw referrer). `:app` wires that callback into analytics; catalog must not depend on `:core:analytics`.
- `RoomLocalCatalog` implements `LocalCatalogPort`; its metadata enrichment transaction updates only an existing subscribed row, so a late Podcast Info response cannot create or restore a subscription after unsubscribe. `RoomEpisodeOfflineLookup` implements `EpisodeOfflineLookupPort`.
- `ports.ListeningHistoryBackupPort`, `ports.SmartDownloadSyncPort`, `ports.QueueSyncPort`, `ports.ActivePlaybackSyncPort`, and `ports.PodcastNotificationSyncPort` keep backup, download, notification topic bindings, and playback seams cleanly decoupled without introducing forbidden `:core:catalog` to `:core:playback` dependency cycles. `ListeningHistoryBackupPort.getAllHistory` may count an episode stored under several IDs once (playback projects it); library export reads `getStoredHistory`, every stored row as it is.
- `sync.UserSyncCoordinator` orchestrates Boxlore Realtime Cloud Sync: batch-bounded dirty push with multi-column optimistic concurrency flag clearing, delta pull, cloud account deletion (`deleteCloudSyncData`), account switch local data purge (history, sessions, daily totals and, through `EpisodeIdentityDao.deleteAllGroupStates`, the shared like and completion settings of episodes stored under several IDs) and active playback session teardown via `activePlaybackSyncPort.stopAndClearActiveSession()`, and coordination across `SubscriptionSyncResolver` (LWW subscription and tombstone resolution, RSS ingestion), `HistorySyncResolver` (active playing episode shield, which covers every stored ID of the playing episode through its `episodeIds` lookup because progress is written to the episode's owner ID; progress LWW; independent like status LWW), and `QueueSyncResolver` (monotonic versioning, 3-way tombstone merge, head-position retention of active episode, and 5-tier metadata hydration). Results are communicated via `sync.SyncResult`, with reactive UI state modelled via `sync.CloudSyncUiStatus`. History and queue artwork never syncs player-only `.collage` links: uploads drop them, downloaded rows store null instead, and `HistorySyncResolver` lets a real address from either side replace one (`HistorySyncResolverTest` covers both). A peer's titled queue item whose cover was dropped takes this device's catalogue cover (`QueueSyncResolverTest`).
- `FolderRepository` and `RoomFolderRepository` manage library subscription folders: creating iconless or icon-assigned folders with optional `showPodcastGrid` 1×1 cover style, updating display sizes, restoring folders from JSON backups (`restoreFolder`), auto-organizing subscribed shows into genre folders (with selectable display sizes and cover styles, while preserving custom and existing folders), auto-syncing subscribed shows matching `linkedGenre` (with canonical genre token matching and Tech/Technology synonym normalization), moving shows between folders on genre customization, adding/removing podcasts from folders, and cascading folder deletions without unsubscribing shows.
- `:core:rss`, `:core:domain`, `:core:database`, and `:core:prefs` are re-exported where existing public signatures require those types.

- `SubscriptionRepository.setAutoDownloadEnabled` uses `AutoDownloadDao` in production to atomically persist the activation boundary and cloud-dirty preference. Notification preferences remain independent. Restored/cloud changes are reconciled by the app download lifecycle; release scheduling does not depend on `markAsNew` or Podcast Index tip updates.

- In `SubscriptionForegroundSync`, the two-request cap (`DEFAULT_FEED_CONCURRENCY`) applies to publisher-feed refreshes, while its Podcast Index chunk sync for not-ready shows and missing-feed-URL recovery keep their own six-request limit (`DEFAULT_PI_CONCURRENCY`). Whole-library callers of `syncSubscriptions` (Smart Downloads, backup restore) are separately limited to two concurrent `/sync` calls (`PI_SYNC_PARALLELISM`).

- `shownotes/ShowNotesParser` interprets publisher HTML with Jsoup without fetching pages. It preserves meaningful anchor labels, resolves relative URLs only with a known base, classifies real domain boundaries and routes, filters infrastructure/media links, and deduplicates tracking variants while retaining case-sensitive paths, query values, and fragments. `EpisodeLinkTitles` removes destination-platform labels (including aliases and generic actions) so they cannot override a URL's profile handle. Social handles use platform-specific profile routes; login, sharing, and other reserved routes are not usernames. Description chapters require at least two valid timestamp/title lines; generated seek links never rewrite existing anchors, attributes, code, or prose clock times. `ChapterRepository` delegates description parsing to this shared parser.
- `crosspromo/CrossPromotionDetector` grades title wording with `CrossPromotionTitles`: feed drops, swaps, recommendations and "New show:" name another show outright; delimited introductions ("Introducing: X", "Listen Now: X", "X: episode one of a new podcast") are possible promotions on their own; trailers, presenters ("Wondery Presents: X"), "Coming soon" and plain "Introducing X" need the episode's own artwork, a trailer-length duration (15–420 s), Trailer metadata or the notes; "Meet", "Bonus", "Trailer:" and "Announcement" need the notes. `CrossPromotionNames` strips seasons, episode numbers, trailer labels, studios, hosts and "new podcast" taglines ("Blood Trails, Season Three" → "Blood Trails"). The host's own seasons and series are refused when the name starts or ends with the host's name, a presenter is the host and the notes do not name the show, the notes call it a season or episode of the host, the title says "our new series" or "new season trailer", or the title or notes describe a Patreon or premium preview. People ("INTRODUCING the RAMPAGE ROOKIES!"), dated events and numbered DJ-mix "presents" titles are refused too. `CrossPromotionDescription` corroborates a name only through an invitation ("Follow Blood Trails on…", "a special preview of X", "X is a new podcast"), never a passing mention or a longer name that starts with it. It also reads "from our friends at X" when a feed drop's title names an episode rather than the show. Explicit feed exchanges compare names exactly, so "Serial" can still be promoted in Serial Killers. `CrossPromotionResolver` searches the full extracted name, then its shorter forms (before a colon or " with "), excludes the host, rejects ambiguous matches, and prefers an unambiguous Apple Podcasts destination. A title also matches without its parenthetical, by its colon head or tail, or with a host added ("Uncharted" → "Uncharted with Hannah Fry"). A lone unnamed Apple link must resolve to a matching title before it can be used; unrelated links fall back to search. Cancellation propagates and transient search failures remain retryable. Its bounded cache expires empty searches after one minute and successful matches after one hour.

## Dependencies

- Project dependencies: `:core:model`, `:core:network`, `:core:domain`, `:core:database`, `:core:prefs`, `:core:rss`, and `:core:ranking`.
- Libraries: Retrofit, OkHttp, Gson, coroutines, DataStore, Firebase Database, Firebase Messaging, and Install Referrer.
- Reverse-edge rule: catalog must not depend on playback, downloads, designsystem, analytics, or feature modules.

- Show-notes HTML parsing uses Jsoup; the library stays inside `:core:catalog` and shared values remain in `:core:model`.

## Threading / lifecycle

- Production repositories are application-scoped through `AppContainer` and `SharedAppDependenciesHolder`.
- Network and database work uses suspend APIs and background dispatchers at repository boundaries.
- Workers and services must use the installed holder instead of constructing independent catalog, RSS, or ranking graphs.
- `PodcastRepository` opens its player SharedPreferences on first use; the legacy-file migration reads from disk, and the repository is constructed on the main thread during startup. Folder links use `FolderDao.addPodcastToFolderIfExists`, so linking to a just-deleted folder is ignored.

## Persistence & identity

- Recommendation interests are trimmed, de-duplicated and capped at 12 (`boundedRecommendationInterests`) on `/recommendations/v2`, the legacy `/recommendations` fallback and the bootstrap recommendations request, matching the API's caps.
- `PodcastRepository.getHomeRecommendations` replaces the old `getHomeBootstrapData`: Home's Picked for you and Explore's For you only used its recommendations, so it now sends `include = ["recommendations"]` on `POST /home/bootstrap` and returns `HomeRecommendations(items, isFallback)` without the Brief fallback fetch. Workers without `include` support still reply with every part, which the app ignores.
- Main Room database identity is owned by `:core:database` and exposed through catalog APIs.
- User preference and cache file names are owned by `:core:prefs` and catalog cache code.
- RSS podcast IDs and negative episode IDs are owned by `:core:rss`.
- Backup JSON field names and backup version fields must remain restore-compatible. Version **6** adds optional `directFeedOptIns`; do not rename those keys. Optional `subscriptionManualOrder` and `homePinnedPodcastIds` must stay nullable for older backups.
- Package root is `cx.aswin.boxlore.core.catalog`.
