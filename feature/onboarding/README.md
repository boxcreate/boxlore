# `:feature:onboarding`

## Purpose

Owns first-run onboarding presentation: genre selection, search-based onboarding, import prompts, AI-guided onboarding, suggestion cards, and completion actions. It does not own preference storage, catalog engines, network client construction, or app navigation registration.

## Public API

- Show covers pass their available artwork alternatives to the shared loader without changing search, suggestions or onboarding decisions.

- Suggestion cards and selectable rows use steady Material feedback. Custom compact actions and genre chips opt into the shared restrained control response, clipped to their actual shapes. Primary action backgrounds contract with their content inside the shared press layer. Selection/subscription callbacks are unchanged.

- `OnboardingScreen` and `OnboardingViewModel` for the flow shell.
- **Echo (AI onboarding), redesigned 2026-10-15.** `EchoOnboardingScreen` is one conversation screen with fixed areas that keep their place on every turn: a top bar (Back, a wavy progress line, Search, and a menu with **About Echo** and **Pick topics instead**), Echo's avatar beside its short reaction, one question, its answers, and a footer of buttons only. There is no transcript, answer receipt, language row or footer link stack.
- **Opening turn (app-owned, no request).** Echo says “Hi, I’m Echo. Tell me what you like, and I’ll pretend I knew all along.” above “Where does your mind like to wander?”, with eight one-word topics that are also the sent answers (`EchoInitialTopic`: Science, Tech, History, True crime, Comedy, News, Business, Health) in a two-column connected grid of equal tiles, each a badge and a one-line label (stacked on tall screens), plus a centred **Something else** text button. Later turns show the API's four choices as one connected group of equal rows (outer corners round, inner corners tight). Every answer carries an icon (`EchoChoiceIcons`: its keyword match, or a distinct topic-free fallback) inside an `EchoSelectionBadge`: a soft circle that blooms into a filled, turned Material shape when picked, each answer its own shape (`EchoBadgeShapes`, rotating through the set each turn), while the tile or row rounds fully and fills with `primaryContainer`; screen readers hear checkbox states. Something else swaps the choices for a text box (500 characters) in the same slot; Back or **Use the choices** swaps back. The language tip is the text box's helper text.
- **Choice icons.** `EchoChoiceIcons` matches whole words (stems of five or more letters), tone before topic, so “space” is science and never a spa. A set shows icons only when at least three of four choices match; the fourth gets a neutral icon, and fewer matches show no icons.
- **No scrolling, on any screen; the layout adapts to spare space.** `EchoLayout` picks a tier from the content height (before the keyboard and footer, so sizes never change between turns), and larger text drops a tier: Spacious (≥680dp), Roomy, Regular and Compact set Echo's size (168 to 84dp), the cards' base height and whether opening tiles stack the badge above the label (Spacious and Roomy) or set them side by side. Echo is always centred like a messaging profile, with its bubble below and a small tail pointing up at it. `EchoBodyLayout` then measures Echo, gives the answers their minimum, gives the question the room left (its type shrinks to fit, `TextAutoSize`), and shares the spare height: cards grow into half of it (up to 16dp each) and the rest goes a little above Echo, mostly between the question and the answers, and the remainder below, so the answers sit just under the middle. An open keyboard folds Echo away, and on the tightest screens (under 400dp, or very large text) the question outranks Echo. When the keyboard closes, the field leaves its typing state and Echo slides back in.
- **Status lives where the next question goes.** While a turn loads, the question and answers leave and a shimmer placeholder in the loaded geometry takes their place (two question lines at the top, four rows in the answer slot); Echo plays its thinking pose and the progress line ripples. The footer stays exactly as the listener last saw it with every action paused (`EchoScreenModel.busyFooter`), and the main button turns tonal and says Echo is thinking: an expressive `LoadingIndicator` beside a word that changes every 1.8 seconds (“Thinking…”, “Pondering…”, `echo_thinking_words`) with a primary-colour glint sweeping across the letters. After 4 seconds Echo's bubble shows a hard-coded, step-specific line (`EchoWaitStep`, `res/values/echo_onboarding.xml` arrays, rotating every 5 seconds) and a 15-second countdown; if it runs out, “Taking a bit longer than usual. Your answer is saved.” Building suggestions does the same on the suggestions screen's loading state for the Echo flow (`EchoBuildWaitNote`), with lines for gathering, finding and sorting and one 30-second countdown across them. Back during a request cancels it and returns the answered question with the answer still picked.
- **When the API refuses AI for this install (2026-10-17).** A next-turn answer of `verification_required` (a limited API session whose Turnstile step-up failed or is off) or `daily_ai_limit` hands over to the topic picker at once (`EchoRequestPolicy.picksTopicsAfter`, then `switchToLegacyOnboarding`), because Try again can't succeed. The step-up itself happens in the network layer while the normal thinking state is on screen. Synthesis and topic synthesis already fall back to charts on any failure, the show deck is skipped, and search/import suggestions keep their **Try again** / **Start without adding** panel, so no path blocks.
- **Errors and recovery.** A failed turn shows an error panel in the question area (“Couldn’t load the next question” / “Check your connection, then try again.”) with **Try again** and **Pick topics instead**. API `recovery` turns show Echo's question with **Find my shows** and/or **Tell Echo more** (opens the text box). A named show (`searchSuggestion`) adds a tonal **Search for “…”** button under the question.
- **Finishing.** Next-turn requests send `features: ["finish_hint", "show_probe"]`, `country` and `languages`. Before `guided.finish` allows it (fewer than three meaningful answers), the footer is just **Continue**. After that, whether the API says `available` or `prominent`, **Continue** stays the main button and finishing is a quiet one-line pill above it: “Up to N more questions · **I’m done →**” (“Last question” at one), which asks “Find your shows now?” in a small dialog with **Keep answering** / **Find my shows**. There is no “Echo has enough” state: finishing is always the listener’s choice, and more answers only improve the suggestions. Without the hint (older Worker) four submitted answers make it available. The seven-turn cap is unchanged. Progress moves one fifth per answer, stops at 80% and fills only when results exist. **Find my shows** (and API `ready` turns) open the shared suggestions screen at once in its loading state; there is no separate Echo generating or ready stage. Back from loading or failed suggestions cancels the build and restores the question it started from (`EchoRequestLifecycle.buildQuestion`); Back from loaded suggestions shows a centred ready stage (`EchoReadyStage`: a larger Echo in its presenting pose above “Your shows are ready”) with **See my shows** and **Change my answers**, which discards the results and the picks inside them (`OnboardingAiStart.withoutResults`) so a rebuild never subscribes shows the listener can no longer see. A restart keeps the stored region (`OnboardingAiStart.freshState`).
- **Show deck, 2026-10-15.** After the second answer the app asks `probe-deck` in the background (`requestShowDeckIfDue`, `features: ["show_probe"]`; next-turn requests now send `finish_hint` and `show_probe`). Two to four usable cards make a deck (`EchoDeckLogic.loaded`); the deck is ready the moment its cards arrive, and every clip starts buffering behind it (`EchoClipPool.prefetch`, one Media3 player per clip prepared at `previewStartSeconds`); a clip still loading finishes on tap. The deck itself takes about 10 seconds, so it opens at whichever comes first once it is ready: the next Continue (before that answer is sent; the answer goes out with the reactions after the last card) or the feed build (Find my shows, the confirm dialog, the turn cap or Echo deciding it has enough), which then starts after the last card with the reactions included (`EchoDeck.next`). A deck held before the build shows even when Echo has said it has enough. If either step comes while the deck is still loading, it waits for it once, up to 8 seconds, behind the usual thinking placeholder (`waitForShowDeck`), then opens the deck, or carries straight on if the deck came back empty or is still loading (it no longer waits after that). Back during the wait returns to the question, answer kept. One deck per conversation: an empty or failed deck (often an off-topic early answer, so the API counted fewer than two) is asked for once more after the next answer, never again after that; rewinding before the second answer drops an unseen deck and its clips. Reactions are big connected buttons in the footer's place (Sounds good / Not for me / I already listen / Not sure → `like` / `dislike` / `listen` / `unknown`), no swiping; a new card ignores taps until it has turned face up. **I already listen** also adds the show to the shows the listener will follow (undone with Back). Back steps to the previous card, undoing its answer; from the first card it returns to the question with the answer still picked. Reactions travel on later next-turn and synthesize requests (`probeReactions`, up to 12).
- **Deck look.** The card's question rides in Echo's bubble, in bold, with a smaller Echo beside a smaller bubble (its tail points back at Echo; mirrored in RTL), so the card gets the height; on the tightest screens the question takes the headline slot instead. The card is the one deliberate break from the app theme: a Prism collector card (`EchoPrismCard`, redesigned 2026-10-16 at the listener's request for something extravagant, so its colours are fixed in `PrismColors` rather than taken from the scheme, every text colour checked against its dark ground). A rainbow edge turns slowly (7 s a turn) round a deep-space ground with pink, sky and violet glows; a starburst turns behind the art (50 s a turn); glitter twinkles at its own angle as the card leans; a rainbow sweep and a glare follow the light. The square art sits tilted 2° in a white-edged, dark-ringed frame with a violet glow and a moving sheen. A foil sticker is slapped on its top corner, turned 12° with a white edge: “TASTE TEST · 01/03” (or “WILD CARD” with a sparkle for `related` shows) in Space Mono, so the deck reads as part of the questions, not as recommendations; screen readers hear “Taste test, 1 of 3”. The name is in Unbounded ExtraBold capitals with a pastel foil gradient (screen readers get the name as written), the publisher a spaced Space Mono line, and the pitch sits in a dark box with a rainbow edge. Unbounded and Space Mono come through the Google Fonts provider (`UnboundedFamily`, `SpaceMonoFamily` in `:core:designsystem`); the card re-plans once they arrive, and the system sans stands in if they never do. Sizing (`EchoPrismLayout`, measured with a `TextMeasurer` exactly as drawn): the words are measured first and the pitch is never cut. The name keeps 24sp while it fits two lines, then steps down to 18sp, and only then takes a third line (down to 16sp, “…” only for an extreme name); the publisher shows only beside a short name (one line, or two at 22sp and up). The art takes the height that is left, up to the card's inner width, and the card (at most 420dp, at least 280dp) narrows to hug the art so there is no empty foil at its sides. When the art would drop under 150dp (small phones, large text) the card switches to a compact arrangement: art (124dp down to 72dp) beside the tag (the role alone) and name, the pitch underneath; on the very tightest slots the pitch steps down to 11sp and, last of all, the art goes. The deck's buttons stop at 60dp at normal text sizes (`EchoDeckRowMaxHeight`) so the card keeps the room on tall screens; large text keeps the tier height. The card floats (a slow few-degree drift, paused in the background and still with animations off), leans away under a finger and wobbles back (`EchoCardPhysics`). Each card is revealed the first time it comes up (`EchoCardRevealTiming`): the first is dealt off the deck face down, turns over with a small overshoot and lands with a haptic tick, then a flash of light runs across the foil (760ms); later cards flip where they lie (560ms). Answered cards are thrown right, left, up or down by reaction while the next one turns over; the rest of the deck peeks out underneath. The clip button sits below the card (the card reacts to touch, so nothing on it is a button): “Play a clip · 0:45” with the episode's title underneath on roomier screens (the same 56dp height on every card, so the card never changes size), a wavy spinner while buffering, pause inside a wavy ring filling over a 45-second clip that fades in and out (`EchoClipTiming`). Answering a card stops its clip; the next card waits for its own tap.
- **Motion.** `EchoMotion.handoff()` is the single change: the old content leaves in 110ms, the new content rises in on a grounded spring after 90ms, and size changes follow a non-bouncy spring; choices then stagger in 45ms apart. Selection morphs shape and colour on springs. All of it follows the system animation scale (instant at zero). The `EchoScreenModel` pure functions decide the screen kind, footer buttons, progress and Echo's pose.
- **Echo avatar.** `EchoFigure` plays the shared `EchoCharacter` from `:core:designsystem` for each moment of the conversation (`EchoMoments`: `EchoScreenModel.avatarPhase` picks the phase, `echoOnboardingMoment` gives its sequence and eye idle). Each moment is a short motion clip that ends on Echo’s resting pose: Welcome waves; each new question asks with an open hand; Thinking gives a thumbs up, then loops writing in a notebook and resting a hand on its chin, with pauses between; Preparing loops shuffling cards and looking through a magnifier; each show card gets a small happy hop; the ready stage fans out its cards; errors rest. While it rests, its eyes follow the moment’s idle script. Each new question or show card plays its moment again (`playbackKey`), with the next clips prefetched. Echo stands on a primary-container stage 1.14 times its resting height, centred on its body (`EchoFigureGeometry` sizes the figure so Echo and the stage both fit), that morphs to a new Material shape and turns 45° on an underdamped spring with each new question (`EchoPlatformMotion`). The Echo beside a show card is 85% of the usual avatar width (`EchoDeckAvatarShare`). Echo pauses while the menu or About sheet is open; with animations off it shows each moment’s resting pose.
- **Echo itself moved to `:core:designsystem` (2026-10-16).** `EchoCharacter`, its manifest model, clip decoding, LED eyes and accent tint now live in the designsystem `echo` package, with the assets in `core/designsystem/src/main/assets/echo-character`, so Account & sync and the library import can use the same Echo; see that README. Onboarding keeps its moments and eye scripts (`EchoMoments`, `WelcomeEchoIdle`). The old `echo-onboarding` sprite strips, `EchoOnboardingAvatar` and `EchoOnboardingMotion` are gone. The face is just two eyes drawn as lit dots on the screen glass, with no mouth; Echo’s body stays still while it rests and only the eyes move, in whole pixels and whole grid cells.
- Echo peeks over the top edge of Welcome's **Find shows for me** button (still with its sparkle icon). It is the new `EchoCharacter` (`welcome` sequence): its eyes start as it starts to rise: it looks down at the button edge it is climbing over, then darts up to the listener with a blink and an eye smile. From then on it reads the headline up and to its left, looks back, checks the button below, smiles, and now and then glances off to the side, curious (`EchoWelcomeIdle`, about 17 seconds a loop). Only the eyes move, never to the right, and something changes at least every 3.5 seconds. It is drawn behind the button so the button's edge sits at Echo's neck (`WelcomeEchoNeckFraction`) and hides its body. Its size adapts to the free space above the button (`welcomeEchoCell`: 96 to 136dp, measured from the room between the invitation and the button), so it fits every phone without fixed sizes; when even the smallest Echo can't fit (short windows, very large text), it stays hidden. Echo rises into place on the shared Welcome clock (420ms with a small overshoot, from 0.7s) and ducks 6dp while the button is pressed, popping back up on release. A faint 11dp contact shadow (20% black, drawn only over Echo's pixels) stays at the button's edge as Echo moves, so it reads as tucked behind the button. Echo is clipped to the button area so its body never shows below the button before it rises, and it never adds layout height, so the page never scrolls because of it. With animations off it shows its still pose. `WelcomeEchoPeekTest` covers the rise curve and the adaptive size; `WelcomeEchoFitTest` (Robolectric) checks fifteen window and text sizes, from a 320x568dp phone to an 800x1280dp tablet, plus an unfolded foldable, both landscape orientations and a split-screen half, at 1x to 2x text. Echo shows on common phones, the unfolded foldable and the portrait tablet, and never overlaps the invitation. These are static sizes; Echo's state across live window resizes is not covered.
- Welcome uses a solid rounded cover panel with 12 curated bundled covers in two opposing, continuously tiled rows. The opening holds a brisk glide for 600ms, then slows over 1.8s directly into a continuous 16dp/s loop. The invitation “You bring the curiosity.” enters before a fixed “We’ve got the” prefix with rotating mysteries, laughs, headlines, big ideas, stories, discoveries and lore. The word and its matching Rounded icon use the theme's primary accent; masked word reveals and a short icon settle share the cover clock, with readable holds and a longer pause on lore. The subtitle reserves the longest localized word's width and height; large text stacks the prefix above the slot rather than shrinking it. TalkBack reads one stable “We’ve got the lore.” description. Headline type size adapts to the window width. The wordmark and all actions remain available from the first frame. The compact, single-line “Find shows for me” action includes an AI sparkle and opens the existing AI-guided discovery flow; connected “Search podcasts” / “Import library” actions include their search/download icons. These actions and “Skip setup” retain their existing callbacks. The normal phone layout fits without scrolling or overscroll stretch; short windows and larger system text can scroll only when content needs more room.
- Onboarding hero titles use `rememberCondensedGoogleSansFamily()` from `:core:designsystem` so condensed Google Sans Flex follows Appearance lettering roundness; AI onboarding uses centralized Google Sans Flex weight tokens.
- `GenreOnboardingScreen`, `SearchOnboardingScreen`, `ImportOnboardingScreen`, `AiOnboardingScreen`, `AiChatOnboardingScreen`, and `AiSuggestionsScreen`. `ImportOnboardingScreen` presents library restoration options (OPML/JSON file import and Sync from Cloud account) with inbound download iconography (`Icons.Rounded.Download`). - **Suggestions screen, redesigned 2026-10-15** (`AiSuggestionsScreen`, shared by Echo, genres, search and library import). A top bar (Back, “Shows for you”) over one vertical list of lanes; each lane is an expressive-shape icon, its title and **Add all** / **Remove all**, then its shows in a sideways row (no lane descriptions), so every lane is visible at a glance. Echo’s flow leads with Echo beside a bubble (“Here’s what I found. Tap to add, hold for details.”) and a **Your picks** lane holding the shows picked during the chat (a “Sounds good” or “I already listen” deck answer, or a search side trip; `aiPicks`, snapshotted at the build), selected and removed from the other lanes. ## Dependencies

- Project dependencies: `:core:model`, `:core:catalog`, `:core:designsystem`, `:core:network`, and `:core:analytics`.
- Onboarding owns step / import / AI glossary events through `:core:analytics` (no PostHog direct).
- Libraries: Compose, Navigation, lifecycle ViewModel/runtime, Coil, coroutines, Retrofit, Kotlin serialization, Material icons, and Media3 ExoPlayer (show deck clips only; listening playback stays with `:core:playback`).
- Reverse-edge rule: feature modules must not depend on other feature modules or read raw preference files.

## Threading / lifecycle

- `OnboardingViewModel` is scoped to the onboarding route or host owner. Echo turn and synthesis jobs cancel on Back, Search, genre fallback and restart. Cancelled work cannot replace a restored question or enter error/catalog fallback; genuine timeouts still recover. Unaccepted turns restore their submitted question/draft/history on cancellation. Empty catalogs enter the existing fallback/retry path instead of publishing an unusable ready state.
- Preference completion writes go through `UserPreferencesRepository` and `BoxcastPrefs` supplied by app wiring.
- Catalog and network actions use injected dependencies and suspend APIs; first publisher-feed persist is handed to application-scoped `SubscriptionForegroundSync` so navigation cannot cancel it.
- UI runs on the main thread. Welcome motion shares one lifecycle-aware frame clock, pauses below STARTED, and resumes without replaying the entrance. The system animation-duration scale is honored; disabling animations reveals the full copy, shows static lore and freezes the reel. The cover reel uses the pre-refresh welcome motion: after three warm-up frames, each row glides 120 dp over 1.08 s on a soft ease-out (`CubicBezierEasing(0.33, 0, 0.2, 1)`), the lower row 96 ms later, while a linear drift of one six-cover loop per 40 s starts at 0.7 s underneath it, so the covers settle without ever stopping. The covers fade up from 55% opacity over the first 0.96 s. `WelcomeEntryTiming` places the headline lines (220 ms and 360 ms) and the reply (700 ms) inside that acceleration with a 700 ms emphasized-decelerate entry, and Echo rises at 1.1 s once the copy has landed. Deck card artwork is prefetched through `ArtworkPrefetch` the moment the show deck arrives, beside the clip prefetch, so cards usually appear with their artwork already in memory. Travel and reveal values are read only by drawing layers, avoiding per-frame composition; the rotating subtitle composes only when its selected word changes. Bundled covers require no network request.
- Genre synthesis handles its network failure inside the `async` child (`orFallbackOnFailure`) and falls back to trending charts. An exception escaping an `async` child fails the parent launch even when `await()` is caught, which crashed onboarding on timeouts.

## Persistence & identity

- This module owns no storage files.
- Onboarding completion flags, selected genres, and recommendation/onboarding caches are owned by `:core:prefs`.
- Preference key names must remain stable in the prefs module.

## Testing notes

- `onboarding_ai_response_received` no longer carries the reply's text (it can repeat what the listener typed); the turn event's typed text is capped at 500 characters in `:core:analytics`.
- `EchoRequestLifecycleTest` covers which API refusals send a failed Echo turn to the topic picker (`verification_required`, `daily_ai_limit`) and which keep Try again. No onboarding ViewModel harness exists, so the switch itself is verified by source inspection.
