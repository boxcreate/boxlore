# `:feature:home`

## Purpose

Owns Home feed presentation, Daily and Offline mixes, and local debug surfaces for ranking diagnostics. It presents data from injected core dependencies and does not own settings (decoupled into `:feature:settings`), catalog engines, ranking persistence, playback services, download workers, or Room schemas.

## Public API

- Hero, grid, Daily mix, Your shows and recommendation artwork retain episode/show alternatives for the shared loader to try after real failures. Spotlight and Your shows remain show-first. `HomeArtworkHandoffTest` covers broken episode art falling through to show art, bounded all-error recovery, accessible labels and a failed Home tile recovering after detail art loads at another size.

- Cards, episode rows and expandable titles use steady Material feedback; custom hero actions, show selectors and compact CTA controls opt into the shared 3% press response. Hero and discovery cards use their native click handlers. Nested play and navigation targets remain independent, and selector long presses still open pin actions. Shared press interaction regressions run in this module's existing native-graphics JVM host.

- Both chapter and child heading text explicitly use `onSurface`, so an artwork-colored navigation shell cannot leak its foreground into a dark Home preview. `HomeHeaderPaletteTest` renders both levels under an inherited black content color on the JVM.

- `HomeRoute`, `HomeScreen`, `HomeFeed`, `HomeViewModel`, and `HomeViewModelAssembler` for the Home route. `HomeRoute` reports after its initial loaded feed has committed two frames so the app shell can begin nonessential launch animation without competing with first-paint work. Foreground subscription latest-episode sync is `:core:catalog` `SubscriptionForegroundSync` (started from AppRoot after onboarding and the initial screen commits). New PI subscriptions observed by Home request the application-scoped full publisher-feed ingest instead of only refreshing a PI tip. Library Subscriptions calls `requestRefresh` on appear so open-app-to Subscriptions is a live sync, not a cache-only paint. Your Shows filter lists call `PodcastRepository.getEpisodesPaginated`, which already unions cached feed extras for PI shows opted into **Missing episodes?** so the chip stream is not PI-only. Selected-show and serial-oldest episode queries fetch with a bounded safe page limit of 100 to eliminate heap exhaustion on deep catalogs. The selected-chip signal also includes `latestEpisodeId` / `rssHasNewEpisodes` so a direct-feed tip promote reloads that list; a successful launch persist also bumps `rssRefreshVersion` for the open chip (`HomeForegroundSyncLogic`). Same-chip reloads swap the list in place (no skeleton). Home calls `preferFeedPodcast` so launch sync refreshes that show first. Available local subscriptions/resume content can reveal Home before remote trending finishes; discovery keeps its own loading state. The filter-chip skeleton remembers its initial 1-row vs 2-row layout (two rows when the count is unknown) for the loading session. Up to five `home_pinned_podcast_ids` prepend the Your Shows cover order (mixtape stays the first chip when there is more than one show; pin 1 is the first podcast after mixtape). Long-press a cover for a Material 3 **Pin** / **Unpin** menu (does not pin on the long-press itself); a sixth pin shows a snackbar and is not added. Pinned covers show a circular pin badge. New unpinned subs still prepend in the remainder, never ahead of pins. Home and Library Smart share the canonical deterministic Your Shows score and one bounded recency floor from `:core:ranking`. `HomeYourShowsRanker` decides when the cover order, Daily Mix and discovery rows are ranked; playback progress never triggers a pass, because ranking on every tick made Home stutter. A pass ranks on the first assembly, once after synced catalog changes settle (new or serial-next episodes, subscriptions from an import or cloud sync: 1.5 s debounce, at most one pass every 5 s), once when Home starts after an episode was started or finished, and when Home starts on a snapshot at least 30 minutes old. A 0.05 score hysteresis prevents tiny changes from moving covers. Subscription and pin changes still update the covers immediately without scoring: new shows join the front and removed shows leave the covers and Daily Mix; new shows join Daily Mix on the settled pass, which also fills a Daily Mix that was empty because episodes had not synced yet. The selected show's episode list has one writer, the selected-show collector, so base Home updates on playback ticks can no longer swap it with the unfiltered list (the cause of rows jumping while something played). Layout in `LibrarySection` is unchanged (≤4 row, 5–9 two rows of 5, >9 interleaved 2-row grid).

## Startup and loading performance

- The two-row Your Shows skeleton draws five cover chips in each row, including while the subscription count is unknown. `YourShowsSkeletonTest` verifies that all ten covers are visible for unknown and known two-row counts.
- Home shares one linear, draw-only `ShimmerScope`, paused when loading sections are outside the visible grid viewport after the 180ms handoff; loading/content sections retain matching keys. The sweep starts with a visible highlight and uses 8%/18% surface contrast so short cached waits still show movement. Discovery and For You poster grids are emitted as lazy two-card rows instead of eagerly composing an entire grid.
- Discovery poster and featured skeletons share the loaded card layout and font-scaled three-line title measurement; the first recommendation uses a compact horizontal featured card. `HomeMixLayout` shares loaded and placeholder landscape dimensions (up to 310 × 142 dp, with height growing for enlarged text). Hero and Your Shows draw loaded content fully opaque underneath an opaque loading cover, then fade only that cover for 180ms. The same shimmer clock continues through the handoff. The cover uses `matchParentSize`, so it does not participate in sizing the loaded section, and is disposed after the fade. A stalled animation keeps the cover/content visible rather than exposing a blank frame. Cached-ready sections skip the cover. Mix cards appear immediately in their reserved rail; mode switches retain the whole-rail/title animation without another entrance animation on every card; empty finished sections stop showing skeletons.
- Subscription selector covers animate placement only, without insertion/removal fades that can hide artwork on an early frame. Same-region bootstrap reloads seed trending from the current snapshot and keep matching editorial rows during refresh; completed responses still replace the snapshot. Discovery cards remain visible while refreshing, and base Home publication cannot overwrite the independently selected category result/loading state.
- Brief artwork is bundled WebP: the Home cover follows the edition weekday, with 28dp curved lower image corners matching the Brief page, while playback uses the fixed branded regional square through the shared artwork mapping.
- The Daily edition Brief card uses an uncropped landscape, live masthead, a single bottom-left date/story/duration line and a solid themed top-right hide control. The opaque Material 3 base gives the headline, Listen/Open brief controls, progress and story previews a defined bottom edge. Open brief uses an opaque primary-container fill to remain distinct from the card in light and dark modes. The card stays on Home until the listener finishes that day's edition or hides it (for today or always). It stays even when the same brief also appears in a resume hero card or grid (`HomeUiAssemblyLogicTest` covers both). The card shows three headlines by default. Story numbers and headlines align vertically; the last visible story row expands/collapses the list instead of adding a separate All stories button. The Home edition switcher is absent; preferences and temporary region selection remain on the Brief page. Hiding today/all and feedback retain explicit confirmation and analytics. Story titles in the card use 14 sp body type in the on-surface colour for readability, and the story numbers use the app's UI font with tabular digits.
- Brief metadata and chapters load independently of Home discovery: the saved default Brief edition is resolved before fetching. Changing it does not reload chart/recommendation flows or change the app region. Home opens the resolved default edition; the Brief page allows temporary edition selection without overwriting that preference.
- Recommendation cache parsing, serialization and scoring run on Default. Discovery rankings are recomputed only when candidates change or on a Your shows ranking pass, using the history and subscriptions current at that pass; history alone changes on every playback tick and no longer invalidates them. The cache resets with region/language/daypart collectors.
- Cold-start reveal: when Home's data arrives together, the skeleton hands over one section per frame (`rememberHomeRevealStage`): the hero first, then Your shows, then the discovery grid. Content already present when Home composes shows at once. Before this, all three composed in one frame, which stalled a cold start for most of a second in debug builds. The shimmer keeps running until the last section is revealed, and the feed only recomposes when the visible-loading answer changes, not on every scroll.
- The hero skeleton mirrors the real carousel: one large card at the carousel's width (it aims for 320dp and keeps a 40–56dp peek after a 16dp gap) and the peek beside it, so content settles in place. The large card follows the chosen hero style (`HeroSkeletonCards.kt`), so each style loads on its own structure: Block is a solid surface-container card with context lines, square artwork in the top end corner, two title lines, a show line and the connected Play/Details row; Cover shimmers where the artwork goes, above a solid shade holding the context line, a larger two-line title, the show line and Play/Details at the card's 20dp insets; Duotone shimmers across the whole card, with the context block at the top and the title, show line and Play/Details drawn on it; Halo draws its ring's track and a cookie where the cover goes, placed by `haloGeometry`, with the context lines beside them. Tide's loading card reuses `TideCardLayout` with a shimmering square, the solid wavy panel and the disc. The peek shimmers like artwork for Cover, Duotone and Tide, and is solid otherwise. Every new hero style adds its own branch to `HeroSkeletonCard`. The skeletons use plain layouts, with no lazy rows, so nothing extra is composed on a cold start.
- `HomeCacheRestoreGate` lets the initial local recommendation / Because You Like caches and fallback flag finish restoring before the first assembled Home snapshot or recommendation refresh. Slow cache reads cannot produce a second startup insertion or overwrite a fresh API result. Empty, malformed, or cancelled restoration releases waiters; API refreshes and their cache writes continue normally afterward. This gate waits only for local storage, never for network completion.

## Threading / lifecycle

- ViewModels are scoped by app navigation or Activity owners.
- Repositories, ports, playback, downloads, prefs, and ranking dependencies are application-scoped instances supplied by app wiring.
- Home surfaces emit glossary analytics through `:core:analytics` (no PostHog direct in the feature).
- Daypart, region, or content-language changes cancel the previous editorial-row load before painting the new
  greeting’s results. Editorial rows load independently from personalized recommendations.
- UI state is exposed through flows and collected by Compose on the main thread.
- Network and database operations run through injected suspend APIs.

## Persistence & identity

- This module owns no storage files or stable preference keys; Home pins are stored as `home_pinned_podcast_ids` in `:core:prefs`. Toggles go through `UserPreferencesRepository.toggleHomePinnedPodcastId` (one DataStore write).
- RSS IDs, ranking database rows, download cache entries, and playback media IDs are owned by core modules.
- Stable Compose test tags include `home_settings_button`.
